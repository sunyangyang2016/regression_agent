# 系统性能异常判定阈值（展示参考）

> **重要说明**：本 Skill **不负责**系统检测与异常判定。
> 所有具体的检测逻辑、阈值标准由 **部署在另一台机器上的远程 MCP 服务器** 完成。
> 本文档仅列出远端服务器通常采用的检测参考值，用于理解前端展示的提醒内容，**不是本 Skill 的执行逻辑**。

## 参考阈值总表

以下为远端系统监控 MCP 服务器通常采用的检测标准（具体以远端服务器实际配置为准）：

| 指标 | 检测方式 | 警告阈值 | 严重阈值 | 说明 |
|------|---------|---------|---------|------|
| CPU 使用率 | 远端服务器采集 | ≥ 85% | ≥ 95% | 持续高占用预警 |
| 内存使用率 | 远端服务器采集 | ≥ 85% | ≥ 95% | 内存耗尽风险 |
| 磁盘占用 | 远端服务器采集 | ≥ 85% | ≥ 95% | 磁盘空间不足 |
| 系统负载 | 远端服务器采集 | load > 核心数 | — | 系统过载 |
| 网络连接数 | 远端服务器采集 | 异常激增 | — | 可能异常流量 |
| 关键服务存活 | 远端服务器检测 | 服务停止 | — | 服务不可用 |
| 敏感端口暴露 | 远端服务器检测 | — | 监听 0.0.0.0 | 安全风险 |

## 提醒数据结构（由远端服务器返回）

远端 MCP 服务器返回的每条异常提醒使用以下结构（本 Skill 原样推送，不修改内容）：

```json
{
    "level": "warning",        // warning | critical（由远端服务器判定）
    "title": "异常标题",
    "message": "详细描述",
    "metric": "cpu",           // cpu | memory | disk | network | process | service
    "current": "85.2%",
    "threshold": "85%",
    "timestamp": "2026-08-04T14:22:00"
}
```

## 兼容返回结构

远端服务器可能返回多种格式，AI 提取异常时需兼容：

1. **直接返回 alerts 数组**：
   ```json
   {"alerts": [{"level": "critical", "title": "...", "message": "..."}]}
   ```

2. **单条状态**：
   ```json
   {"status": "warning", "level": "warning", "title": "...", "message": "..."}
   ```

3. **嵌套 results**：
   ```json
   {"results": [{"level": "critical", "title": "...", "message": "..."}]}
   ```

4. **顶层直接是数组**：
   ```json
   [{"level": "critical", "title": "...", "message": "..."}]
   ```

## 本 Skill 不包含的检测逻辑

以下检测均由远端服务器完成，本 Skill **不实现**：
- CPU/内存/磁盘/网络指标采样
- 异常阈值比对与判定
- 服务存活探测
- 端口安全扫描

本 Skill 只做（由 AI 执行）：**调用远端 MCP → 接收检测结果 → 运行 scripts/push_alert.py 推送 → 前端展示**
